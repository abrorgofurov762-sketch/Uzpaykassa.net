# Якуний тайёрлик ҳисоботи (ўзбекча)

## Ҳозирги ҳолат
Бу пакет GitHub'га жойлаштириш ва Render'да назоратли текширувни бошлаш учун тартибланган. Лекин уни реал пулли операцияларга 100% тайёр деб тасдиқлаш мумкин эмас: ташқи Mostbet сервери, ҳақиқий API рухсатлари ва пул ҳаракати бу муҳитдан текширилмаган.

## Текширилгани
- Python файллари компиляция/синтаксис текширувидан ўтказилади.
- `tests/` папкасидаги тестлар ташқи API'ни тақлид қилган ҳолда ишлайди.
- Mostbet депозит API'си калитлар бўлмаганда ёки live flag ўчирилганда рад жавоби бериши керак.
- Таймаутдан кейин молиявий POST автоматик такрорланмайди; натижа номаълум бўлса, операция қўлда текширилиши шарт.
- ZIP'га база, `.env`, лог ва `__pycache__` киритилмаган.

## Реал ишга туширишдан олдин шартлар
1. Render'да `BOT_TOKEN`, `ADMIN_ID` ва `/var/data` persistent disk'ни созлаш.
2. Mostbet API калитларини фақат Render Environment'га киритиш.
3. `MOSTBET_LIVE_DEPOSITS_ENABLED=false` ҳолатида `python tools/mostbet_preflight.py` ишлатиш.
4. API баланс жавобида касса валютаси `UZS` эканини тасдиқлаш.
5. Банк хабарларининг ҳақиқий намунасида тўловни аниқлашни текшириш.
6. Провайдер билан келишилган, ҳисоб эгаси рухсат берган минимал реал синовни алоҳида режа ва транзакция reconciliation билан ўтказиш. Ҳужжатда sandbox йўқлиги кўрсатилган.
7. Номаълум, такрорий ёки ноаниқ операциялар учун админнинг қўлда reconciliation жараёнини текшириш.

## Ҳали ишлаб чиқилмаган ёки тасдиқланмаган
- Mostbet серверида ҳақиқий депозит ва пул ҳаракати.
- UZS рухсати айнан шу кассада live API жавоби билан тасдиқланиши.
- 1xBet, Melbet, Betwiner, WinWinBet'нинг ишлайдиган API интеграциялари — placeholder.
- Реал банк/карта хабарлари ва Render'да қайта deploy/restart ортидан маълумотлар сақланиши.

Шу сабаб `MOSTBET_LIVE_DEPOSITS_ENABLED` қийматини live verification ва рискни қабул қилишгача `false` қолдиринг.
